# Datastar 1.0.2 → 1.0.4 Integration

Date: 2026-09-21

Vendored runtime bumped from 1.0.2 to 1.0.4 in one step (1.0.3 is subsumed; the
three signal-ordering code paths StarHTML depends on — proxy auto-create,
`__ifmissing` merge, markup-order attribute loop — are byte-identical across
1.0.2/1.0.3/1.0.4). Each upstream changelog item was checked against StarHTML's
surface and decided individually below.

## Patch pipeline

1.0.4 aliases `document` to a minified local (`p=document`). Both patches
(`shadow-dom-scan`, `outside-race-fix`) anchored on the literal `document`, so
they now capture the alias (`«doc»`) and the outside-handler parameter name
(`«arg»`) from their landmarks. The re-anchored definitions apply cleanly to
both the 1.0.2 and 1.0.4 bundles (regression-checked), and
`verify_datastar_patches.py` passes on the built core.

## Addendum 2026-09-21 (later session): StarElements adoption + first-scan fix

- **`datastar:scan` vs the deferred first scan (fixed, `7d4a3ea`)**: Datastar defers its first scan to a
  timeout and then scans `roots.size ? [...roots] : [documentElement]`. A StarElements host connecting before
  that timeout dispatched `datastar:scan`, the patched listener registered the host as a root, and the document
  was never scanned (no `datastar-ready`, every page-level `data-*` dead). The listener now leaves light-DOM
  hosts to the pending document scan and defers shadow roots to `datastar-ready`. Browser coverage:
  `tests/browser/test_starelements.py` (run with `--with-editable ../starelements --with-editable .`; a bare
  `--with-editable ../starelements` resolves a cached starhtml wheel with stale static JS).
- **Rocket adoption list, outcome** (StarElements repo, commits `1a30122`…`9d208cf`):
  1. `data-scope-children` — done; hosts listen for `datastar-scope-children`, rescope is idempotent.
  2. attribute-aware rewrite — done; `Local._id` is `$$name` so `data-bind/indicator/ref` carry `$$name`
     (a bare name keeps page scope; `Input(data_bind=Local)` previously bound the page signal — this also
     affected the devtools filter inputs). `__root` escapes to page scope. Renames keep attribute order
     (same-element declaration-order rule).
  3. pre-upgrade `data-ignore` guard — **not applicable**: hosts render bare, `$$` lives only in inert
     `<template>` content, and the one live-DOM path (SSE into a host) is handled synchronously by (1);
     hydration (`data-star-id`) is not emitted server-side and skips rewriting by contract. A late-inserted
     host is covered by `test_late_host_codec_fallback_and_declared_events`.
  4. CSP — done; component scripts compile through a nonced `<script>` (`document.currentScript.x=…`), nonce read
     from any script's `.nonce` IDL (Datastar consumes `data-nonce`). Found and fixed on the way: the host's
     `data-signals` declaration was applied *after* setup and clobbered synchronous setup writes; it is now
     `data-signals__ifmissing` (devtools reads either).
  5. named errors + codec fallback — done (`StarElementsError(reason)`; int/float/json strict, attribute values
     fall back to the template default with `CodecParseError`).
  6. manifest — done (`ElementFactory.manifest()` → `{tag, props, slots, events}`; `events` reach the template as
     `data-events`, `emit()` warns `UndeclaredEvent`).
  7. nested signal paths — not done (flat-name devtools contract).
- **`Signal(..., reset=True)`**: already expressible as `ifmissing=False` (plain `data-signals="{…}"` object,
  hoisted ahead of readers); documented on `Signal`, and `signals(name=value)` is the handler-side reset.
  `_declarations_first` now orders `data-signals*` before `data-computed*`.
- **Read-before-declaration lint**: `starhtml.lint.check_signal_order(ft)` walks a rendered tree in document
  order and reports reads on an earlier element than the declaring one (undeclared reads are not reported).
- Observed, not changed: `Span(data_text=computed)` SSRs the expression text (`($count * 2)`) as fallback content.

### Review pass (three independent reviewers, same day)

All eight Datastar claims the fixes rest on were confirmed against `library/src` and a live Chromium (deferred
first scan over `roots.size ? [...roots] : [documentElement]`; `datastar-ready` once, after the document root is
observed; `datastar-scope-children` synchronous, inner/outer + morph only, before the observer; attributes applied
in `dataset` order; lazy computeds; `.nonce` IDL readable; keyless `data-signals__ifmissing`; observer re-applies
renamed keys). Two caveats worth keeping: a pojo-valued `ifmissing` patch still replaces a non-object live value,
and a renamed `data-computed:` key leaves the old computed in the store (computed plugin returns no cleanup).

Fixed from the findings: `__root` was not idempotent across later patches and let `$$` through (modifier now
kept in markup); nested hosts were re-prefixed by the outer rescope; a patch re-sending a host's bare outer
markup wiped and hid it (re-rendered from the hook); one bad template default aborted every later registration;
empty numeric defaults became `null` (a merge-patch delete) — now codec zero values; the lint missed `$user.name`
roots and bare `data-bind="x"` reads and mis-declared nested object keys / string literals; the slot-attrs path
in `html.py` appended declarations after readers; the deferred shadow scan ran for hosts disconnected before
`datastar-ready`; two browser assertions were satisfied by SSR fallback text. Not changed: `set_timeout(...,
store=Local)` emits `$$$name` (was already wrong before `Local._id` changed); the first-scan test's host-before-timeout
order is scheduler dependent (it asserts `datastar-ready` fired exactly once, which fails on the old listener in
Chromium).

### Patch modes + `apply()` export (same day, later)

append/prepend/before/after/replace and selectorless patches into a host get no upstream hook; StarElements
now pre-scopes the fragment text in a capture-phase `datastar-fetch` listener (runs before the engine's
bubble-phase watcher dispatch; `argsRaw` is mutable). All seven shapes are browser-tested
(`test_patch_modes_into_host_are_prescoped`). Handoff item 5 investigated: exporting `apply` upstream is not
enough on its own — the deferred first scan skips the document once any other root is observed — so the
proposal has two parts (export + always scan the document on the first pass). Details and a draft issue:
starelements `docs/designs/2026-09-21-patch-scoping-and-apply-export.md`. Filing it is a separate step.

### Definition ordering (same day, final)

Rocket queues element definitions until `datastar-ready`; StarElements defined at DOMContentLoaded, which is
the root cause of the first-scan starvation. StarElements now gates `initStarElements` on the `ready` promise
the `datastar.js` wrapper exports (`scripts/build_datastar.py`; registered before the first-scan timeout).
With the original naive `datastar:scan` listener all 16 StarElements browser tests pass, so the guarded
listener (`7d4a3ea`) is defence in depth, not the fix. Upstream ask reduces to exporting `apply` (+ a
readiness query); see starelements `docs/designs/2026-09-21-patch-scoping-and-apply-export.md`.

### Final boot/scan contract (same day, after critiques)

The `shadow-dom-scan` patch now exports the engine's (tree-shaken) `apply(root, observe)` instead of adding a
`datastar:scan` listener; the wrapper's `ready` promise is gone. StarElements defines after DOMContentLoaded +
one macrotask (ordered after Datastar's first-scan timer by the static import), never scans light DOM (document
observer), and calls `apply(shadowRoot, true)` for shadow roots. Measurements and reasoning: starelements
`docs/designs/2026-09-21-patch-scoping-and-apply-export.md` (Final section). Upstream ask: export `apply`.
